# ROUTR v2.1 — improvement plan (2026-09-25)

Branch: `feat/exploring-and-implementing-new-stuff`

## Analysis — where ROUTR stands

| Area | State | Gap |
|------|-------|-----|
| Routers | 19 situational + 5 depth + router + catalog, all pass `validate-skills.sh` | No router for **performance** (slow pages, bundle size, profiling, slow queries overall) — today it scatters across debug/frontend/database |
| Depth fallbacks | debug, frontend, plan, ship, test | **Security** has no depth fallback, yet it is the highest-stakes router to run half-equipped |
| Evals | 5 files, 55 prompts, covering router/debug/frontend/test-qa/video | 14 routers have **zero** eval prompts; nothing **runs** the evals — they are documentation, not a quality gate |
| Validator | 5 mechanical checks | Doesn't check description budget, `Not for:` presence, SKILL.md line cap (docs say ≤150), broken relative links in `references/`, or eval JSON validity |
| Install drift | `~/.claude/skills/routr-*` differs from repo in ~30 files; 15+ removed `*-playbook` stubs are still installed | No tool to detect drift or prune legacy stubs — users silently run stale routers and see duplicate/deprecated entries in their slash menu |
| Metadata | `.plugin/plugin.json` says `1.3.0`, "22 workflows"; README badge says 25 | Counts and version are stale |

The core insight: **routing quality is decided by the ~200-char `description` alone** in most hosts. Everything that protects descriptions (length budget, `Not for:` boundaries, collision detection, evals that actually execute) has the highest leverage.

## Plan

### Track A — tooling (scripts/, .github/)
1. `scripts/validate-skills.sh` new checks:
   - 6. description ≤ 320 chars (FAIL), > 280 (WARN)
   - 7. situational routers include `Not for:` (FAIL); depth/catalog exempt
   - 8. SKILL.md ≤ 150 lines for routers, ≤ 200 for depth (FAIL)
   - 9. every relative markdown link in `skills/**.md` resolves (FAIL)
   - 10. every `evals/*.eval.json` parses; every `expected_router` / `expected_chain` / `must_not_load` entry names an existing `skills/routr-*` folder (FAIL)
   - 11. every situational router has ≥1 eval prompt as `expected_router` somewhere in `evals/` (WARN)
2. `scripts/run-evals.py` (stdlib only): builds the router menu from each SKILL.md frontmatter, then for each prompt:
   - `--mode static` (default, offline, deterministic): lexical scorer over `Use when:` triggers minus `Not for:` phrases — a smoke test for description overlap
   - `--mode claude`: shells out to `claude -p --model <model>` with the menu + prompt, parses the chosen router
   - reports accuracy per file, per-boundary failures, and `must_not_load` violations; `--json` output; non-zero exit under `--min-accuracy`
3. `scripts/sync-installed.sh` + `.ps1`: diff repo `skills/routr-*` against installed roots (`~/.claude/skills`, `~/.agents/skills`, `~/.cursor/skills`, `~/.codex/skills` if present); `--apply` copies; `--prune-legacy` moves removed `*-playbook` stubs (list from docs/naming.md) into `<root>/.routr-legacy-backup-<date>/` (never deletes)
4. CI: run validator + `run-evals.py --mode static` (report only, no accuracy gate yet)

### Track B — content (skills/, docs/, README, INSTALL, .plugin)
1. New router `routr-perf` (Core Web Vitals, bundle size, render profiling, slow API/query, memory leaks). Full reference set. Registered in router tree, decision-tree overlaps, resolution precedence, registry.
2. New `routr-depth-security` fallback (OWASP-style checklist: authz, injection, secrets, RLS, SSRF, deps) wired into `routr-security` bootstrap.
3. Update README/INSTALL/architecture/authoring (new checks, eval runner, sync script), bump plugin.json to `2.1.0` with correct counts.

### Track C — evals (evals/)
1. Add eval files so every situational router has ≥3 prompts incl. ≥1 adversarial boundary pair: ship, plan, ai, agents, database, security, deploy, refactor, review, explore, integrate, mobile, marketing, motion, perf.

### Verification
- `bash scripts/validate-skills.sh` passes
- `python scripts/run-evals.py` runs over all evals; report accuracy
- `scripts/sync-installed.sh` dry run shows the drift; apply + prune to the local skills folder

## Results (2026-09-25)

- `validate-skills.sh`: all 11 checks pass; 2 WARNs (`routr-debug` 284 chars, `routr-video` 295 chars over the 280 soft budget).
- `run-evals.py --mode static`: 91/153 (59.5%), a lexical baseline only. Its misses are mostly adversarial boundary prompts, as expected for keyword overlap.
- `run-evals.py --mode claude`: not run yet because the local `claude` CLI was signed out. The runner now checks sign-in before it starts.
- `sync-installed.sh --apply --prune-legacy` against `~/.claude/skills`: 16 drifted routers resynced, 2 new ones installed, 23 legacy `*-playbook` stubs moved to `.routr-legacy-backup-20260925/`.
